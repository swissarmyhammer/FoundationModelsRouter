## What
The write-ahead card (01M6GK7RHHHC6B6QMJ25FT1QDT) records a `.toolCallStarted` marker when a tool call starts. The live `toolCall` and running `toolStatus` events still go out at the END of the submission (`emitSessionEvents` in `Session/RoutedSessionActorRecording.swift`). A host that shows progress sees a call only after it ended.

An early version of this change failed 4 existing tests: `SessionObserverSeedingTests` (grouped rows) and `ToolInvocationLivenessTests` (event order). Cause: `SessionObserver` closes the narration text of a pass only when the open text row is the last row. An early call row stops the narration from joining its call group.

## Do (design first, in a task comment)
1. Change `SessionObserver` so an early call row does not break the grouping of narration text with its calls (group by pass, not by row order).
2. Emit `toolCall` and a running `toolStatus` from the started-marker path (`RoutedSessionActor.deliver(invocation:)`), once per call id. The end-of-submission diff skips the ids already emitted (keep a set of started ids).
3. Update the tests that assert the event order, with a reason for each change.

## Acceptance Criteria
- [ ] A host sees `toolCall` and running `toolStatus` when the call starts.
- [ ] No call is announced twice.
- [ ] The observer rows group the same as before for a clean run.

## Tests
- [ ] Extend `ToolInvocationLivenessTests` and `SessionObserverSeedingTests`. Run the full `swift test`.
