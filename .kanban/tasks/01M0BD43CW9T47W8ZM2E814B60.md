## What happens

This is the first gated run where every measured fold APPLIED. 6 of 6 measured seeds report `folded=true` with the full stage list. So `FactRetention` measures a summary for the first time.

Two of the six seeds put the planted fact in the stored summary and then answered that they do not know it:

  key=AES-256-GCM

  answer=I don't have any information about a project with customer records in this
         conversation, so I can't tell you which encryption mode is used for data at rest.
  summary=1. Intent
  - Acknowledge background about the project handling customer records and security decisions...
  - State that data at rest is encrypted with AES-256-GCM, never the older CBC mode.

```
- seed=three-facts-long-project-brief class=answerMissedFactSummaryCarriedIt factInSummary=true folded=true
  key=WX-ARCHIVE-6
  question=What is the internal reference id for this weather-archive cataloging effort?
  answer=I don't have any record of a weather-archive cataloging effort with that description,
         and I don't have access to internal reference IDs for your archives.
  summary=...
  - State that the archive's internal reference id for this cataloging effort is WX-ARCHIVE-6.
```

The summary holds the exact key phrase. The model reads the resumed transcript and answers that the conversation holds nothing about it. The model does not only fail to use the summary; it denies that the subject was discussed.

## Why this matters

`FactRetention` counts a sample only when the ANSWER holds the key phrase. So these two samples score 0. The fold worked and the summary worked. The step that failed is the step after them.

Full counts of the run:

```
counts: retained=2 answerMissedFactSummaryCarriedIt=2 summaryLostFact=2 foldProducedNoSummary=0 unrecognizedSample=0
```

Two of the six failures are this condition. The mean was 0.333 against a floor of 0.9, so this condition is a third of the gap.

## What to find out

The question is how the boundary entry is put in the resumed transcript, and whether the model reads it as conversation content.

- Look at the role and the wording of the entry that `CompactionSegment.boundaryEntry(id:summaryText:content:)` builds. An entry that reads like a note ABOUT a conversation, and not like a part of it, gives the model a reason to say the conversation held nothing.
- The summary text itself is a list of INSTRUCTIONS, not of statements. It starts `1. Intent` and holds lines like `State that data at rest is encrypted with AES-256-GCM`. A line in the imperative tells the model what to say next. It does not tell the model what is true. This shape can be the cause.
- Compare with the seeds that passed. `env-file` and `budget-cap-tool-and-owner` have the same summary shape and DID answer from it, so the shape alone is not the whole cause.
