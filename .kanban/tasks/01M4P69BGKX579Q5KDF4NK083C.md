title: Give the no-op tool call check to a restored session

## Problem

Task ^rw72f4j added `SessionConfiguration.isNoOpToolCall` (`NoOpToolCallCheck`). A vended session and a fork have the check. A restored session does not: `RoutedModel.restoreSession(id:recordingRoot:instructions:tools:toolOutputProtection:)` and `restoreSessionTree(...)` take no `SessionConfiguration`, and the sidecar does not record a closure. So a restored session uses `SessionConfiguration.defaultIsNoOpToolCall`, and a no-op tool call while an operation is pending does not stop the generation.

## Task

- Add an `isNoOpToolCall` parameter to the two restore surfaces, with the default `SessionConfiguration.defaultIsNoOpToolCall`, the same shape as `toolOutputProtection`.
- Give it to `makeRoutedSessionActor` for each restored node in `SessionTreeRestoration.swift`.

## Acceptance

- A test: a restored session with a check stops at a no-op tool call while a run is pending.
- A test: a restore with no check runs a no-op call as before.
