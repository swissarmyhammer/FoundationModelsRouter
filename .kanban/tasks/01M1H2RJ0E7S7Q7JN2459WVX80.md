## What
Give a host a public live signal that a tool's elicitation is pending. Option 1 of the ask: a `SessionEvent` case that carries the `.elicitation` `OperationEvent`.

Files:
- `Sources/FoundationModelsRouter/Session/SessionEvent.swift`: add `case elicitationRequested(OperationEvent)`. Doc comment: the event's `elicitation` is the typed `ElicitationRequest`; its `elicitationId` is the id `RoutedSession.respond(elicitationId:response:)` and `complete(elicitationId:)` take; the event's `correlationID` is the posting run's token, or the mounting run's token for a run mounted through `ToolContext.mount(_:op:as:)`. The case travels on `streamSessionEvents()` always, and on the turn's `streamEvents()` when the elicitation is raised inside a turn.
- `Sources/FoundationModelsRouter/Session/RoutedSessionActorRunJournal.swift`: in `record(event:)`, after `append(partial:)`, add `if event.kind == .elicitation { deliverLive(.elicitationRequested(event)) }` beside the existing `.completed` branch. The mailbox registers the pending entry before it runs `posting` (`SessionMailbox.awaitAnswer(to:posting:)`), so the host can answer the moment it sees the event.
- `Sources/FoundationModelsRouter/Session/RoutedSession.swift`: list the new case in the `streamSessionEvents()` and `streamEvents(to:maxTokens:)` doc comments.
- `Sources/FoundationModelsRouter/Hosting/ToolContext.swift`: in the `elicit(_:)` doc comment, say the request reaches a host as `SessionEvent.elicitationRequested`.
