## Problem

A prompt that reaches the reasoning limit loses all its work. The FoundationModelsACPAgent session reported this from a SWE-bench run on 2026-10-05: 16 django instances, model `mlx-community/Qwen3.8-27B-mxfp4`. In 2 of the 16 instances the prompt ended with `prompt.stop_reason=_reasoning_limit` and an EMPTY patch. These 2 are the largest loss in the run. Earlier runs on 2026-10-01 had the same failure: 13447 and 14016.

- django__django-13710: 1088 s, tokens.in=144653, tokens.out=29046.
- django__django-13964: 2058 s, tokens.in=1233016, tokens.out=45956.

Evidence (read-only, in the agent repo):
- `FoundationModelsACPAgent/bench/preds.code-context.transcripts/django__django-13710/01M460H04P6D49QAZ3GNRE65ZP/transcript.jsonl`
- `FoundationModelsACPAgent/bench/preds.code-context.transcripts/django__django-13964/01M463CMSNG9DJXGSRDY2027CT/transcript.jsonl` and its `session.json`
- `FoundationModelsACPAgent/bench/run.code-context.log`, lines 2678 and 8020.

Settings in force, from `session.json`: `reasoningTokenLimit` 8192, `recoveriesPerTurn` 2, `passTokenLimit` 16384, budget `limit` 262144 with `trigger` 0.8.

## What the model did at the limit

In both instances, 3 passes stopped at about 8,000 reasoning tokens each: the first stop, then the 2 recoveries. No compaction occurred, because the peak fill was about 0.2. Each stopped pass took about 250–434 s. These are the long gaps that the agent saw.

### 13710: a reasoning loop

- Seq 393 had 34,741 characters. Only 142 of its 719 lines were unique, so about 80% of the lines were repeats. One 6-line `__init__` block occurred 35 times.
- Seq 401 was the same: 153 of 766 lines were unique. It ended with "I'm clearly stuck in a loop."
- The repetition watch stopped passes 1 and 2, but only after about 8,000 tokens. The 2,048-token window did not fill early, because the loop put a new line between its repeats.
- `repeatedPartRemoval` kept 25,571 of 34,741 bytes. Thus most of the loop stayed in the render.
- The third stop was a reasoning-limit stop.

### 13964: long deliberation that progressed

- Unique lines were 296/369, 291/388 and 250/371 in seq 1475, 1478 and 1481. The context was about 50k tokens, so a large context did not cause the problem.
- The model wrote "Let me write the fix" 6 times, but it never made a source-file edit. The only writes were `repro_issue.py` and `repro2.py`. Nothing reverted an edit. The fix was only in the reasoning.

After each recovery, the model reasoned again in both instances. It made no tool call after seq 393 (13710) or seq 1472 (13964).

## What the recovery does now, and why it fails

The code is in `Sources/FoundationModelsRouter/Session/RoutedSessionActorReasoningStop.swift` and `RoutedSessionActorRepetitionWatch.swift`.

1. `noteReasoningLimit` stops the call. The stop marker cuts nothing (`keptUTF8Lengths: [:]`), so the render keeps all of the 8,192 tokens of reasoning, which is not closed.
2. `continueAfterWatchStop` sends `reasoningStopContinuationPrompt` ("Do not reason more. Act now: call a tool, or give your answer.") as a new prompt. The repetition stop sends `repetitionStopContinuationPrompt` in the same way.
3. The next pass runs with thinking ON. The chat template opens a new think block. The model then reasons again for one more full pass. The text "do not reason" does not stop a Qwen3 thinking pass. In 13710, the long loop in the render also tells the model to continue the loop.
4. `nextRecovery` is shared by repetition stops and reasoning stops for the whole answer. For an agent, the whole answer is the whole SWE-bench prompt with all its tool calls. After 2 recoveries, the third stop returns the response text of the stopped attempt (`responseText(of:excluding:)` or `continueAfterReasoningEnd`). That text is empty. Thus the answer ends with no output, and all the work of the prompt is lost.

## Fix (proposed; the owner must decide each limit, see memory "no invented limits")

1. **Run the recovery pass with thinking off.** `LiveModelLoader.respondWithoutReasoning(to:maxTokens:)` already sends `ContextOptions(reasoningLevel: .custom("no_think"))`. That sets `enable_thinking=false` for a model whose template has the flag. Today it is only for a call with no tools. Add a way for the continuation attempt of a reasoning stop or a repetition stop to send this reasoning level on the tool-calling path. Then the model must write a tool call or text. A model that always reasons, or a model with no thinking control, keeps the current behavior.
2. **Make the recovery prompt short and direct.** For example: "Stop reasoning. Your next output must be one tool call that makes the change you decided on, or your final answer." Close the stopped reasoning in the render before the prompt, so that the model does not continue it.
3. **Do not end the answer with no output after the last recovery.** When no recovery is left, run one final pass with thinking off, and tell the model to give its final answer with what it knows now. If that pass also gives nothing, return a non-empty text that states the stop. Do not return an empty string.
4. **For a repetition loop in reasoning, cut more.** Today `repeatedPartRemoval` keeps about 70% of a loop that is 80% repeats. Check why the cut keeps so much, and keep only the new lines.
5. **Optional, needs a decision:** a reasoning limit that scales with the task, or a count of recoveries per pass and not per answer. Ask the owner before you change `defaultReasoningTokenLimit`, `defaultRecoveriesPerAnswer` or the scope of the count. Do not change a number without approval.

## The stop report

`SessionEvent.reasoningStopped(ReasoningStop)` already has `reasoningTokens`, `limit`, `passFinishReason` and `recovery`. But:
- The run journal (`transcript.jsonl`) has no row for a reasoning stop or a repetition stop. The stop reason is only in the log of the host.
- The final `TokenUsage` and `SessionAnswer` give only `finishReason = .reasoningTokenLimit`. They do not give the limit, the tokens or the count of recoveries that were used.

Add to the report: (a) a journal event for each watch stop, with the kind, tokens, limit and recovery number; (b) on the final answer, the stop that ended it, with the limit, the tokens and the recoveries used of the recoveries allowed. Then the host can log, for example, `reasoning.limit=8192 reasoning.tokens=8070 recoveries=2/2`.
