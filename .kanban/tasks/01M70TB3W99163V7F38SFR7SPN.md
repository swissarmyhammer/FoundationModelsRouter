## What
Make the router load a GGUF reference through llama.cpp with no backend named in the profile.

- Package.swift: add the `FoundationModelsExtrasLlamaCpp` product (FoundationModelsExtras main at 730fe7a or later) to the library target, and add `.interoperabilityMode(.Cxx)` to every target. All targets need it, because the C++ modules of FoundationModelsLlamaCpp spread to each target that links it, even through a wrapper, as Extras measured.
- `LiveModelLoader.init(reporting:cacheDirectory:tokenProvider:)`: build `HubModelLoader(cacheDirectory:tokenProvider:drafterRegistration:gguf: LlamaCppModelLoader(cacheDirectory:tokenProvider:))`, so a `.gguf` reference loads through llama.cpp.

## Already verified
With `.Cxx` on every router target, `swift build --build-tests` passes and `swift test` passes all 2443 tests (2026-11-09). Without the GGUF loader, the router also builds and passes against Extras 0c9952d, including its ModelRef path change.
