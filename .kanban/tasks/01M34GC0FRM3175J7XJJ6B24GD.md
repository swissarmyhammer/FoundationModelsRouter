title: Report the usage of each generation call in a turn

## Problem

A turn that uses tools makes many generation calls inside one `backend.respond` or `backend.streamResponseFragments` call. Router stamps usage one time for each turn. A reader cannot tell a model that reasoned too long from a context that filled up. Evidence: django__django-13964, 2026-09-21: 41 rounds, one usage stamp (tokensIn 1,955,561, tokensOut 53,634).

## What we know

- `MLXFoundationModelsSessionBackend.streamResponseFragments` (`Sources/FoundationModelsRouter/Resolution/LiveModelLoader.swift:298`) sees each snapshot in `observe`. `snapshot.usage` is the usage of the generation call that made the snapshot, and `snapshot.transcriptEntries` shows the entries of that call. `recordLastGenerationCall` keeps only the last one.
- Router wraps every mounted tool (`Hosting/ToolRun.swift`), so each tool call open and close is already visible to the session.

## Do this

1. When the last entry ID of a snapshot changes, or when a tool call opens, emit one per-call record: fed tokens, generated tokens, finish reason (ceiling or natural end), entry kind (text, tool call), and the measured context after the call.
2. Send it as a `SessionEvent` and write it to the run journal, so a recorded transcript shows each call.
3. Do not change any compaction policy in this task.

## Acceptance

- A test with a fake backend that makes three generation calls in one turn gets three per-call records with correct counts.
- The turn-level usage stamp stays the same.
