## What
Add `Tests/FoundationModelsRouterTests/CrossRouterResidencyTests.swift`, a hermetic suite over stubs. Reuse the `LoadSpy`, `StubModelLoader`, `StubProbe`, `StubMetadataSource`, footprint constants, and `makeRouter` shape from `PooledResidencyTests.swift`. Move the shared stubs into `Tests/FoundationModelsRouterTests/Helpers/ResidencyStubs.swift` so nothing is copied.

Each test builds two `Router`s. Both get the same `ModelPool()` unless the test says otherwise. Each router gets its own `LoadSpy` so the test can tell which router's loader ran. Both routers take the same `StubProbe` and `headroomReserve: 0`, because `hostBudget()` stays per router and a budget pin across two routers holds only when both price against one machine.

## Acceptance Criteria
- [x] Two routers on one pool that resolve one profile load each ref one time; the second router's loader records zero loads.
- [x] A release from the first router keeps the model resident; the second router's session still answers; zero evictions.
- [x] A release from the last router evicts every model one time, and the eviction runs through the loader of the router that loaded it (the first router's spy counts the evictions, the second router's spy counts zero).
- [x] A second router's resolve prices the first router's residents: a disjoint profile whose union with the first router's trio exceeds the budget throws `ResolutionFailure`, and `failure.budgetBytes` equals the host budget less the first trio's footprint.
- [x] Two routers on two different pools do not share: each ref loads two times.
- [x] Fork ceiling, first router wins: router A with `maxConcurrentForks: 1` loads the key; router B with `maxConcurrentForks: 4` over the same pool admits one in-flight fork, not four. Use the suspending-fork shape from `ForkConcurrencyTests.swift`.
