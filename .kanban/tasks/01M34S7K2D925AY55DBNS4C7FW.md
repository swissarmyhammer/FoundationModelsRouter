title: Delete the terminal detail tail cut; a background run's output stays in the tool
---
## Decision (from the owner, 2026-09-22)

`ToolContext.terminalDetailTailLimit` (4,096 characters, `Hosting/ToolContext.swift:22`) must go, and so must the design it patches. The output of a background run (a shell command, a build, a test run) is collected in the tool and is NOT returned to the calling model unless the model asks for it. A settled run's terminal event carries a short report, never the output. There is nothing to cut.

The owner's words: "the output of a shell tool is supposed to be collected in the tool, not returned to the calling model unless it is asked for". Background shell commands are handled in FoundationModelsMultitool, which buffers all shell output. The tool side of this contract exists.

## What is wrong today

- `ToolRun.inBandFacts` (`Hosting/ToolRun.swift:205-210`) puts the tool's whole return value in the terminal's `detail`.
- The mailbox keeps that `detail` cut to its last 4,096 characters (`SessionMailbox.swift:440-459` `boundingDetail`), `wait` reports the cut copy, the settled envelope carries the cut copy (`BackgroundToolRunner.swift:195`, `PendingRunEnvelope.swift:38-42`), and the restore path cuts a recorded event's `detail` again (`Recording/SessionTreeRestoration.swift:603, 629`).
- `BackgroundTool.swift:18` tells a tool author to keep the envelope under the limit.
- The number came from commit 8e9566f (2026-08-04) with no reason. The cut keeps the tail, while the one host-set cap (`TokenBudget.toolOutputLimit`, `ToolOutputCapping.swift:19`) keeps the head. Two rules for one thing.

## The contract

A background tool's return value is a short report: what ran, how it ended, and how to get the output. The run plane carries that report as it is, in the mailbox, in `wait`, in the envelope (pending or settled inside `inlineSettleGrace`) and in the journal. The model asks the tool for the output when it wants it. `inlineSettleGrace` stays (owner decision, 2026-09-22); it carries the same report.

## Do this (Router side)

1. Delete `terminalDetailTailLimit`, `SessionMailbox.boundingDetail`, and the cut in `SessionTreeRestoration.swift:629`. The terminal's `detail` is the tool's report, uncut, everywhere.
2. Delete the doc rule at `BackgroundTool.swift:18`. Write the contract above into the `BackgroundTool` protocol doc: the return value of a background call is a short report, never the output; the output stays in the tool.
3. Keep `PendingRunEnvelope.replacing(detail:)`. The capping layer still uses it to apply the host-set `toolOutputLimit` to a settled envelope's report.
4. Update the tests that assert the cut (`SessionMailboxTests`, `BackgroundToolRunnerTests`, `SessionTreeRestorationTests`; search `terminalDetailTailLimit` and `boundingDetail`). Replace them with one test: a settled run whose report is 10,000 characters reaches `wait`, the envelope and the restored session whole.
