## What

"Session" is one of the named surfaces to cover, but the tracing set has no span for how a session comes into being. Add one. The restore path is the one that earns it most: it reads a transcript tree from disk and rebuilds state, so its cost is real and invisible today.

- Instrument the shared factory `makeRoutedSessionActor` (Sources/FoundationModelsRouter/Session/RoutedSessionActor.swift:8, constructing at line 40), so all three construction sites are covered at once: `RoutedLLM.swift:156` (a new session), `Recording/SessionTreeRestoration.swift:368` (a restored session), and `Session/RoutedSessionActorForking.swift:158` (a forked child).
- Span name: `FoundationModelsRouter.session` from `RouterTracing`. Kind: `.internal`.
- Attributes: `router.id`, `model.ref`, the new `session.id`, the parent `session.id` when there is one, and the origin (`new`, `restored`, or `forked`).
- A forked child therefore carries both a `FoundationModelsRouter.fork` span and a `FoundationModelsRouter.session` span. The fork span measures the wait for a slot; the session span measures the construction. Nest the session span inside the fork span, and state this in the doc comment so the pair does not read as double counting.
- For the restore path, put the span around the tree read and the rebuild, not only the actor construction, so the disk work lands inside it.
