## What

Found during ^cx1type. One plain `swift test --skip-build` run (right after a parallel stress run ended, load average about 16 over 5 minutes) had one issue:

- `AnswerCancellationEntryPointTests.cancellingAStreamingAnswerFinishesTheStreamWithCancellationError`, display name "cancel() finishes a streamEvents answer with CancellationError, leaving the consumer what it already received": `BoundedWait.swift:114:25: Issue recorded` from `BoundedWait.conditionReached("the first streamed chunk at the consumer")`.

So the consumer did not get `HookedSessionBackend.firstStreamedChunk` inside the bound, before the test called `session.cancel()`. The wait was added in ^zr22hpd (commit ce3c0bf). The next 3 full runs passed (1487 + 17 + 19).

The ^cx1type change (`isWorkCancelled` reads the cancel marks of the delivered messages) is not on this path: no mark is set before the test cancels, and the failed wait comes before the cancel.
