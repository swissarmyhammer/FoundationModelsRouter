## What
Add a `DispatchSource` vnode watcher (`.write`) for the `inbox/` folder of each live durable session. Put the watcher type in a new file `Sources/FoundationModelsRouter/Directory/SessionInboxWatcher.swift`; wire it in `RouterSessionDirectory.swift`.

- Keep the watcher in the registry `Entry` next to `stateFeed`. Cancel it in every place that cancels `stateFeed`: `unregister(_:)` (called from `RoutedSessionActor.close()`), `takeArchived` (archive), `liveSummaries()` when it drops an entry whose session is gone, and `register` when it replaces such an entry.
- Start at `register(_:kind:parentID:requestedByClient:)` (this also covers a restore, because a restored session registers) for a session where `ledgerDirectory(of:)` is not `nil`. If the session is still registered (second `register`), keep the old watcher and start no second one.
- `register` is `nonisolated` and runs under `state.withLock`: create `inbox/` and open the file descriptor outside the lock.
- The event handler holds the directory weakly (no retain cycle) and hops onto the actor with a `Task` that calls `scanInbox(of:)`.
- The first action of the watcher is a scan, because files can arrive while no process owns the session.
- On each event, scan the full folder. Do not process one file for each event (events merge).
- A memory-only session gets no watcher.
- Only the process that owns the root delivers: the directory of that process is the only one that registers sessions. Add a comment that says this.
- Decision (open decision 3 of `mailbox-plan.md`): a file in the inbox of a recorded session that is not live does NOT start a restore. Do not add a watcher on all inbox folders of the root. The file waits until a process opens the session.
- Add a count of open watchers that only tests read (`internal`), for the leak check.

## Acceptance Criteria
- [ ] A file that a test moves into `inbox/` of a live idle session is delivered with no call to `send(_:)`.
- [ ] A file in `inbox/` before `register` or restore is delivered at start.
- [ ] A `.tmp` file and a dot file are ignored.
- [ ] The count of open watchers is 0 after `close()` and after `archive`, and a new file is not delivered after them.
- [ ] Two `register` calls for one session start one watcher, and a file is delivered one time.
- [ ] A memory-only session starts no watcher.
