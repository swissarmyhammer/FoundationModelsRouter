## Signal used

The executor channel of each pass. SessionLanguageModel.Executor now relays the channel of the wrapped executor (PassOutputRelay; same pump + buffered forwarder shape as the Extras generate relay). Each event is checked by reflection for a public output fragment: TextFragment (response or reasoning appendText), TextSegmentReplacement, or ToolCalls.ToolCall.ArgumentsFragment. Metadata and usage do not count. The first output event is the first token. It is reported only when a later output event of the same pass follows it. A pass that sends its whole output in one event gets no split. The old transcript-growth watch in LiveModelLoader is removed. The SDK does not put tool-call arguments into the live transcript during a pass, even when the executor streams them, so that watch could never see them. The new test proves this: it failed on the old code with streamed arguments.

## Why the real MLX tool-call-only calls still have no split

The MLX allowed-tool path (mlx-swift-lm MLXLanguageModel.runAllowedToolGeneration / runAllowedToolTurn) buffers the response text and the tool calls in AllowedToolGenerationResult. It sends them (emit / emitToolCall) only after the generation loop ends. Only reasoning text streams. So a tool-call-only pass with no reasoning puts nothing on the channel until the end. ResponseStream snapshots and the transcript are built from those same events, so they show nothing earlier either. The only in-pass signals, the generationObserver task-local and ExecutorPromptCacheSlot.prefillDidEnd, are internal to MLXFoundationModels. These calls now get generation.first_token_seen=false with generation.call_ms, instead of no data. The fix belongs in the fork: follow-up card 01M5EB4PNHG7K0YF7NJ4G1PDRZ.
