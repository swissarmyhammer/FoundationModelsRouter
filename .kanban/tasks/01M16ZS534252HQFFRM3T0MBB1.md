title: Make the default implementations of the public container and backend protocols public

## What

Found while writing the plain-import example in ^tf6dwx1.

`LoadedLLMContainer` and `LanguageModelSessionBackend` are `public` protocols. Their
default implementations, however, sit in extensions that carry no access modifier,
so every default is `internal` and stops at the router module boundary:

- `Sources/FoundationModelsRouter/Resolution/ModelLoader.swift` — `extension LoadedLLMContainer`
  holds the defaults for `languageModel`, `makeSession(instructions:tools:)`, and
  `makeSession(transcript:tools:)`.
- `Sources/FoundationModelsRouter/Session/LanguageModelSessionBackend.swift` —
  `extension LanguageModelSessionBackend` holds the defaults for
  `streamResponseFragments(to:maxTokens:)`, `makeFork(tools:)`, and
  `replacingTranscript(_:)`.

Result: an application outside this package that conforms to either protocol must
write all six members itself. `languageModel` is the worst of them. Its type is
`any FoundationModels.LanguageModel`, and a container that wraps something other
than an SDK model has no value to give. The only honest body is
`preconditionFailure`, which is what the internal default already does. So the
integrator is forced to copy library code to get back the library behaviour.

`ModelLoader.evict(container:)` shows the correct shape: that extension member is
declared `public`, so it reaches an out-of-module conformer.

Card ^9j7pyd5 recorded the same defect from the ^jp93e7c side and is archived as a
duplicate of this card. Its content is merged here: the sibling protocols it named
are listed in the sweep criterion below, and a plain-import consumer that writes its
own container gets `type 'X' does not conform to protocol 'LoadedLLMContainer'`.
