## Problem

On flint5 django-13447 (2026-11-14), committer 01M7E7QXCMFHW40972TQ0206GF called `runCode` with `{}`. The SDK decoded the arguments before the tool ran and threw `LanguageModelSession.ToolCallError` over `GeneratedContent.ParsingError` ("does not contain a property 'code'"). That error escaped as a model failure and ended the agent run ("run.outcome=failed").

## Fix

`RejectedToolCallRetry(error:declaredToolNames:)` now also takes a `ToolCallError` whose underlying error is a `GeneratedContent.ParsingError`. The reason is `invalid_arguments`, the tool name comes from the error, and the detail names the missing property ("The arguments have no \"code\" property, and the tool needs it."). Otherwise the detail is a general text. The detail never copies the argument text. The call then goes the rejected-call way, and the ^7s1stvw rebuild keeps the context.

A `ToolCallError` over any other error still fails the answer.

## Test

`RejectedToolCallRetryTests`: "a tool call whose arguments do not decode goes back to the model". It failed with the escaped ToolCallError before the fix.
