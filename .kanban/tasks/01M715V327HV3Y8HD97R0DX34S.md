## What
Found by the gated GGUF suite (^44meq1j). The router recovers from a reasoning stop with a final pass that has reasoning off (`ReasoningOffRequest`). That pass only reaches a model that conforms to `ReasoningSwitchable`, and only `MLXLanguageModel` conforms (Sources/FoundationModelsRouter/Resolution/LiveModelLoader.swift). `LlamaLanguageModel` does not conform, and FoundationModelsLlamaCpp has no "reasoning off" level: `PromptInputs.applyReasoningLevel` maps `.custom(text)` to the `reasoning_effort` template argument and never sets `enable_thinking = false`.

Measured on 2026-11-09 with `ggml-org/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf` at maxTokens 128: the answer made 4 generation calls. Each one ended with 128 reasoning tokens. The log said "no recovery is left, so a final pass with the reasoning off follows" twice, but that final pass still reasoned. So a GGUF thinking model never gets the reasoning-off pass that the MLX path gets.

## Likely shape
- FoundationModelsLlamaCpp: a reasoning level that renders with `enable_thinking = false`, for example the same `.custom("no_think")` value the MLX engine reads.
- Router: `LlamaLanguageModel: ReasoningSwitchable`, with `canTurnReasoningOff()` returning the template's `supportsThinking`.
- A hermetic test in the router, and the gated GGUF suite then expects the final pass to answer with reasoning off.
