## Cause in Router

1. `RoutedSessionActorRepetitionWatch.swift`, `runFinalPass` and `finalPassPrompt`: the final pass runs through `runContinuation` with the same `body`, so the tools of the session are available. But the prompt tells the model to give a final answer only. For an agent, the work is in a tool call, not in the final text.
2. The recovery prompt and the final prompt do not tell the model what it repeated. When the model repeats the same tool call, a general "do not repeat" text does not stop the loop. Recovery 2 made one different call and then went back into the loop.
3. Identical tool calls (same tool name, same arguments) are caught only by the line window. That needs many calls of about 67 tokens each.

## The "Unexpected EOF" report

The agent saw 4 `runCode` calls that failed with "Unexpected EOF (line N)", and it asked whether a repetition stop cut a snippet in the middle of the tool-call code and then ran it.
- This transcript has no "Unexpected EOF" row. A search of `transcript.jsonl`, `session.json` and `session-history.json` found no match. No `generationCall` row ended at a token ceiling.
- In Router, `RepeatedPartRemoval` keeps a `.toolCalls` entry whole (task ^dzw15st). The rebuild removes a call that got no output. `checkToolCallForRepetition` throws before a tool body runs when the watch stopped the call. So from the code, Router does not give a cut snippet to a tool.
- Do this first: get the run directory of the 4 calls from the agent session, and confirm or refute the cause. If the cause is in Router, fix it in this task. If it is not, write the cause here and tell the agent session.

## Fix (proposed)

1. **The final pass of a session with tools must be able to act.** Change `finalPassPrompt` so that it lets the model make one tool call that makes the change now, or give its final answer. For example: "No recovery is left. Stop reasoning. If a change is not made yet, make it now with one tool call. Then give your final answer with what you know now." Keep reasoning off. If the final pass makes a tool call, let the tool loop continue to its end. `finalPassRan` already makes sure that a later stop gives `stoppedAnswerText` and not another final pass.
2. **Name the repeat in the recovery prompt.** When the stop found a repeated tool call, the prompt names it. For example: "You called `files.read` with the same arguments N times. The output does not change. Do not call it again. Make the change with one tool call, or give your final answer." Take the name and the count from the stopped attempt.
3. **NEEDS A DECISION (owner):** stop a loop of identical tool calls earlier, with a count of identical consecutive calls (same name, same arguments) and not only with the token window. The count is a new limit, so the owner must decide it, with the default and the scope. Do not invent a number (see memory "no invented limits").
4. **Do not let the final text claim a change that was not made:** that is the agent's concern. Router only makes sure that the final pass can act. Write this on the card for the agent session.
